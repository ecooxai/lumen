What changed in the engine

CSS values and CSSOM

Radius shorthand and corner pairs now share strict, atomic validation. Specified values serialize canonically; computed values come from the native style representation, including separate horizontal and vertical values.

Negative math, relative lengths, percentages, declaration priority and invalid-value retention have explicit controls.

Actual geometry

Painting and clipping use elliptical corners, the correct width and height percentage references, and a shared overlap rule. Hit testing preserves the corresponding clip geometry and positioned-descendant behavior.

The real-window check below verifies a vertical-only change through the linked application’s automatic redraw path. A separate bounded 1×1 mask-repeat repair stays within the existing background-colour approximation; it does not claim complete CSS Masking support.

Scope and remaining work

  • Standalone URL conformance work remains deferred, as requested. Existing required regression gates were preserved.
  • The selected radius parsing/computed group is complete; this does not establish Chromium parity across HTML, all CSS, networking, storage, workers, media or the full WPT suite.
  • Radius animation with mismatched one-value/two-value endpoints remains a separately recorded limitation. The complete radius-animation family and computed-endpoint work remain deferred at a reviewed isolation boundary.
  • Opaque pending variable shorthands retain the existing broader partial-mutation provenance limitation.
  • Correct escaped-fixed hit testing adds a measured traversal cost. The 5,000-node no-fixed outside p50 was 0.158µs on held 2102, 293.956µs on accepted 2104 and 396.422µs on accepted 2105. Old escaped-fixed hits were incorrect (0/300); both accepted candidates return 300/300. Each diagnostic ran once, and the native hit code is unchanged between 2104 and 2105. Slower absolute 2105 values are retained without rerun or causal/general-browser-speed claims; the report includes all p50/p95 values.
  • Targeted sanitizers instrument specific style and hit-test units; they are not full-engine/V8 sanitizer coverage. Short single-sample executions do not establish CPU peaks.
