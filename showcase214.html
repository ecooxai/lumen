What changed in the engine

Parsing follows execution

Document streams retain their tokenizer state. Script fetches yield to the event loop, deferred work keeps its order, and replacement documents cancel obsolete jobs.

Components keep the right owner

Custom-element creation and reactions follow the parser lifecycle. Template contents, cloned Documents and imported nodes retain real native ownership.

Variables resolve consistently

Token-aware parsing handles cycles, selected fallbacks, invalid computed values, math whitespace and brace blocks. Basic cycle and syntax files now pass completely.

Frames can reload the same source

Source assignments queue navigation even when text is unchanged. Source-document precedence, pending load accounting and stale-response cancellation are preserved.

Remaining compatibility work

  • Full origin/layer/rule rollback, registered-property animation and several computed-style serialization paths remain incomplete.
  • One document-streaming popup/opener case requires broader browsing-context work. The clone scope retains an inert Document.write/declarative-shadow-root gap.
  • One custom-element anchors expectation differs from the current existing-parent insertion rule; the detailed report records the reference disagreement.
  • URL conformance remains deferred. This release is not a full security audit or a portable binary distribution.

Reviewable source and provenance

All 642 recorded build inputs match the tested source. The source archive includes the separately reviewed public Git history and an offline-verified restore procedure. It excludes private task text, operational records, profiles and credentials. The export has not been independently rebuilt.
